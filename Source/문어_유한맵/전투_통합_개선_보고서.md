# 문어지지마 전투 통합 개선 보고서

작업일: 2026-10-25 (한국 시간)

## 후속 수정 — 하단 밀착 및 해안 카메라 추적

- 전투 HUD의 하단 오프셋을 74에서 0으로 변경하고 기본 표시 크기를 1.3배로 확대했다. 하단을 기준으로 확대하므로 기존보다 위로 올라오는 정도는 최소화된다.
- 조작 안내를 HUD와 겹치지 않는 왼쪽 아래 두 줄로 정리했다. 좁은 화면에서는 중앙 HUD를 우선한다.
- 일반 필드 카메라 추적에서 `FiniteBeach.ClampCamera`를 제거했다. 캐릭터의 이동 가능 지형 검사는 유지하며, 해안 끝에서도 카메라가 실제 캐릭터 위치를 따라가 화면 중앙에 유지한다.
- 해변 상하좌우 끝의 이동 제한과 카메라 중앙 추적을 실제 플레이 모드 검사에 추가했다. 하단 해안 화면은 `Logs/CombatIntegration/camera-edge-bottom.png`에서 확인할 수 있다.

## 결과 및 검증 범위

현재 작업 폴더의 Unity 프로젝트에 반영했다. Unity 6000.5.7f1의 실제 에디터 플레이 모드에서 로컬 호스트를 시작해 통합 검증을 실행했고, 최종 결과는 **PASS, 검사 항목 5,676개**다. 이 숫자에는 반복적인 지형 경계 샘플 검사도 포함되며, 독립적인 게임 시나리오 5,672개를 의미하지 않는다.

전체 요구사항이 모두 완료된 것은 아니다. 특히 실제 2인 네트워크 세션, 전체 애니메이션 프레임의 아트 품질, 첨부 이미지의 손그림 보스 구역과의 정확한 일치는 아래 미완료 항목을 참고해야 한다.

## 몬스터 스폰 및 지형

- `BeachGeometry`의 일반 필드와 보스 필드 윤곽을 플레이어 이동, 스폰 및 이동 제한에 공통 적용했다.
- 배경 위치와 스케일은 `ArenaBuilder`의 동일한 정의를 참조한다. 카메라 위치나 해상도는 스폰 지형 판정에 관여하지 않는다.
- 일반 몬스터 200회 생성 검사에서 지형 유효성과 플레이어 최소 거리 조건을 확인했다. 200회 중 적어도 150마리 이상 생성해야 하는 밀도 검사도 통과했다.
- 윤곽은 보수적으로 추적한 다각형이다. 픽셀 단위 자동 지형 분류나 새로운 Tilemap 제작을 수행한 것은 아니다. 해안 가장자리의 세밀한 통행 폭은 추가 플레이 검토 대상이다.

## 보스 구역·피격 판정·애니메이션

- 기존 `OctopusBossPattern.Arena`의 월드 좌표 정의를 유지했다. 해상도에 따라 공격 구역을 다시 계산하지 않는다.
- 타격 타원을 구역과 해변 안에 넣도록 중심과 반경을 조정했다. 반쪽 패턴의 타원 반경 변경은 공격이 구역 밖으로 잘리는 문제를 바로잡기 위한 변경이며, 체감 회피 난이도에 영향이 있으므로 추가 플레이 평가가 필요하다.
- 30회 릴레이 공격, 4방향 반쪽 패턴, 팔 6개의 독립 HP, 팔을 모두 파괴한 뒤 본체를 10초간 공격하는 구조를 유지했다.
- 준비/복귀 상태의 다리가 접촉만으로 피해를 주지 않는 기존 방식과 플레이어의 기존 피격 무적 시간을 유지했다. 피해는 패턴의 실제 contact 시간에 적용한다.
- 본체 사망 시 팔을 즉시 종료하고 보스 상태를 정리한다. 본체 무력화 시에는 정지된 본체의 일반 접촉 피해를 발생시키지 않는다.
- 포인트 필터링과 프레임 내부 UV 샘플링으로 픽셀 흐림 및 인접 프레임 번짐을 줄였다. 땅에 닿는 다리 기준 위치를 해변 안쪽으로 보정했다.
- 원본 애니메이션 이미지, 기존 GUID 및 원본 시트는 덮어쓰지 않았다. 메시 변형과 타이밍을 조정했으며, 새로운 연결부 픽셀아트나 전 프레임 재작화는 하지 않았다.

## 요소 아이콘과 하단 HUD

첨부 순서와 관계없이 실제 그림과 내부 ID를 확인해 연결했다.

| 표시 이름 | 내부 ID |
|---|---|
| 안개 | ComboId.Fog = 1 |
| 고추 | ComboId.Chili = 2 |
| 나무 | ComboId.Tree = 4 |
| 레몬 | ComboId.Lemon = 12 |
| 탄산수 | ComboId.Soda = 11 |
| 청염 | ComboId.BlueFlame = 13 |

- 첨부 원본 두 장을 `Resources/CombatHud`에 bytes로 보존했다. 원본과 복사본 SHA-256이 일치함을 확인했다.
- 아이콘 분리 및 연결된 외부 배경 제거는 런타임에서 한 번 수행하고 캐시한다. 원본 이미지 파일을 수정하지 않는다.
- 속성 4개, 요소 3개, 큰 특수요소 슬롯 1개와 HP 게이지를 원본 슬롯 배치에 맞춰 하단 중앙에 구현했다.
- 빈 슬롯에는 아이콘이나 쿨타임을 표시하지 않는다. 변신 또는 다운으로 자동 기술이 정지되면 슬롯도 대기 상태로 표시한다.
- 실제 타이머의 남은 시간/전체 주기로 복구율을 계산한다. 어두운 아이콘 위에 `Image.Type.Filled`, `Vertical`, `OriginVertical.Bottom`의 정상 색상 아이콘을 겹치고 원형 Mask를 적용한다.
- 특수요소도 실제 발동 시의 전체 쿨타임을 별도로 동기화하므로 이후 업그레이드가 바뀌더라도 기존 발동의 표시 기준이 바뀌지 않는다.
- 기존 CanvasScaler와 하단 중앙 Anchor를 사용하며 좁은 화면에서는 HUD 폭을 축소한다.
- 네트워크 필드가 추가되어 프로토콜 버전을 4에서 5로 올렸다. 함께 플레이하는 두 실행본 모두 같은 수정 버전을 사용해야 한다.

## 미완료 및 추가 확인 항목

1. **손으로 그린 빨간 구역의 정확한 월드 경계:** 기존 코드에 정의된 사각형 Arena를 유지했다. 이미지에 그린 본체 주변의 오목한 경계까지 동일하게 구현했다고 판단할 수 없다. 정확한 Polygon 경계나 기준점이 확정되어야 한다.
2. **다리 애니메이션의 전 프레임 아트 품질:** 대표 공격 프레임과 4방향 화면을 확인했지만 모든 연속 프레임의 연결부·실루엣·픽셀 크기가 완벽하다고 보증하지 않는다. 원본의 서로 다른 포즈에서 생기는 형태 변화와 긴 다리 변형은 추가 연속 재생 검토 및 필요 시 원본 보존형 재작화가 필요하다. 본체와 각 지면 다리를 잇는 새로운 연결부 아트는 만들지 않았다.
3. **실제 두 클라이언트 네트워크:** 이번 통합 실행은 로컬 호스트 1명 기준이다. 추가 NetworkVariable의 원격 수신, 지연 환경, 합동 필살기 및 2인 보스전은 별도 실행본으로 검증해야 한다.
4. **장시간 전 스테이지 및 기존 저장 데이터 회귀:** 데이터·합성 규칙 검사는 통과했지만 전 스테이지를 순차 클리어하거나 기존 저장 데이터를 불러오는 시나리오는 실행하지 않았다.
5. **피격 마스크의 근사 오차:** 본체 알파를 64×64로 샘플링하므로 외곽선과 작은 투명 구멍에서 약간의 오차가 있다. 다리 피격 범위도 이동 목표를 따르는 근사 원형 범위이며 전 실루엣의 프레임별 PolygonCollider를 제작한 것은 아니다.
6. **출시 빌드:** 이번 검증은 Unity 에디터 플레이와 C# 컴파일 기준이다. 새 Windows 배포 실행 파일은 만들지 않았다.

추가 검증을 전체 완료로 오해하지 않도록 위 항목은 완료로 처리하지 않았다.
