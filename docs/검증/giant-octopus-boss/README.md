기존 Beach.bytes 필드와 플레이어 원본, 사용자의 3.58초 동작 참고 영상 및 배치 스케치를 참고했다.

## 선택한 1번 촉수의 정지 자세

### 사용자 9자세 스케치의 도트 시안

움짤: [tentacle-pixel-nine-poses.gif](tentacle-pixel-nine-poses.gif). 생성 시트에서 번호를 제외한 각 자세를 잘라 1~9 순서로 650ms씩 표시한다. 560×560, 9프레임, 총 5.85초, 무한 반복. 솟은 자세는 바닥, 아래 방향 자세는 위쪽 출입구를 기준으로 배치했다. 연결 작화를 추가한 스킬 애니메이션이 아닌 정지 자세 순차 미리보기다. 저장 GIF를 다시 열어 프레임 수·총 길이를 확인하고 9프레임의 잘림을 육안 검토했다. 재생성: `python tools/render_octopus_boss.py --pixel-poses`.

`assets/tentacle-pixel-nine-poses.png`는 새 스케치의 1~9번 형태를 3×3으로 배열한 도트 디자인 참고 시트다. 기존 분홍 몸체·빨판·짙은 외곽선을 참조했으며 1~4 솟기·휘기, 5~6 접기·잠복, 7~9 아래 방향 타격 자세를 비교한다. 내장 image_gen 생성, 1328×1184 RGBA. 주변에 반투명 색 번짐이 남아 있으므로 게임용 최종 스프라이트/애니메이션 시트가 아니다. 배경 정리 재생성은 도구 안전 필터에 차단되어 첫 생성본을 보존했다. 프롬프트와 상태는 동명 JSON에 기록했다. Unity 및 기존 GIF 미적용.

## 원화와 연결 프레임 구분

- **생성 원화**: assets/body.png 한 장. 내장 image_gen을 사용해 스케치의 안경·3자 입·팔짱을 반영했다. 최종 프롬프트는 PROMPT.txt다. 첫 생성본은 최종 배치에서 사용하지 않는다.
- **촉수·돌·지면 원화**: 생성 AI 프레임이 아닌, 재현 가능한 곡선·윤곽·레이어 드로잉이다. 준비/웅크림/들기/가속/접촉/반동/회수의 곡선 키 자세를 제작했다.
- **연결 프레임**: 키 자세의 제어점을 시간축 3차 Hermite 곡선으로 연결하고 매 프레임 윤곽과 빨판을 새로 그렸다. 한 장의 촉수 PNG를 늘이거나 프레임을 페이드한 방식이 아니다. 접촉 유지 구간은 고정하고 그 밖의 연결 속도를 이어 준다.
- 촉수의 기본 반지름은 약 19px에서 12px로 완만하게 변하며, 빨판은 곡선 길이 약 20px 간격으로 재배치한다. 길이가 바뀌면 보이는 빨판 수가 바뀌는 **절차적 시안**이며, 최종 게임용 피부 텍스처의 고정 UV 애니메이션은 아니다.

## 투명 PNG / 스프라이트 시트

모든 PNG 에셋은 RGBA다. 셀은 **384×288px**, 가로 **8셀**, 좌→우, 위→아래 순서다.
미사용 마지막 셀은 투명하다. 기본 재생 속도는 **25fps**이며 마지막 완결 자세가 한 프레임 포함된다.

| 시트 | 프레임 수 | 행 수 | 뿌리 피벗 (왼쪽 위 기준 px) |
|---|---:|---:|---|
| slam-sheet.png | 30 | 4 | (70, 235) |
| ground-sheet.png | 61 | 8 | (170, 235) |
| grip-throw-sheet.png | 49 | 7 | (70, 235) |

assets/manifest.json에 셀·프레임 수·순서·피벗과 30회 접촉 및 8회 투척 시간/좌표가 들어 있다.
오른쪽 팔은 수평 반전하여 사용한다. 바닥 기준 피벗은 화면상 고정이며 지면 출입 중에도 바뀌지 않는다.
단독 PNG: body.png, slam-first.png, slam-contact.png, ground-first.png, grip-throw-first.png,
rock-held.png, rock.png, ground-back.png, ground-front.png.

시트의 접지 레이어는 확인을 위해 촉수와 함께 그려져 있다. 별도 뒷구멍/앞모래 PNG도 제공한다.
구멍 뒤 → 촉수 → 앞모래·자갈 순서다. 잠복은 투명도 페이드가 아니라 지면 아래 이동과 마스크 가림이다.
바위는 뒤쪽 감긴 촉수 → 돌 → 앞쪽 감긴 촉수 순서로 그리며 투척 전까지 팔 끝의 같은 좌표에 붙는다.
마지막 잡기와 첫 비행은 같은 중심·반경 23px·회전각 0에서 이어진다.

## 검토 및 한계

- 실제 GIF의 접촉·투척 연속 프레임을 디코딩해서 확인했다. 확대 팔의 링 외곽선과 GIF 팔레트를 수정했다.
- 30회 이벤트는 팔마다 5개씩, 카운터는 접촉 이후 증가한다. 여섯 뿌리는 공격 동안 고정된다.
- 반쪽 난타는 여섯 촉수의 뿌리를 고정하고 각 팔을 수직으로 내려친다. 끝이 실제로 닿는 자리에 얕은 눌림과 짧은 균열을 만들고, 작은 모래·자갈이 팔 끝 양옆으로 튄다. 타격 자국은 팔 사이에서 서로 이어지지 않게 해 각 접촉과 촉수 빨판이 계속 읽힌다. 중앙을 포함한 지정 구역을 팔 실루엣으로 덮으며 팔별 반복 간격은 0.40초다.
- 지면 출입은 움푹한 어두운 구멍, 밝은 모래 경사, 앞쪽 흙턱·자갈, 출입 먼지를 구멍 뒤→팔→앞턱 순서로 겹쳤다. 05-detail.gif에서 지면 아래 이동과 출현을 확대해 확인했다.
- 지정 구역으로의 뿌리 이동은 완전히 지하에 가려진 뒤에만 이루어진다. 원래 위치 복귀도 같은 규칙이다.
- 원본 필드는 픽셀 아트, 보스는 요청한 굵은 선의 분홍 만화체다. GIF는 256색이고 촉수는 절차적 드로잉이므로 참고 영상의 손작화 품질과 같다고 보장하지 않는다.
- 체력·무력화·그로기 10초·본체 약점은 추후 전투 구조로만 유지했다. 이번 GIF는 네 공격을 검토하는 시안이며 해당 전투 상태 전환을 구현하지 않는다.

## 재제작

저장소 루트에서 Python + Pillow로 실행한다. 본체 PNG는 먼저 assets에 보존해야 한다.

```powershell
python tools/render_octopus_boss.py
python tools/render_octopus_boss.py --sheets
python tools/render_octopus_boss.py --pattern 1
python tools/render_octopus_boss.py --pattern 2
python tools/render_octopus_boss.py --pattern 3
python tools/render_octopus_boss.py --pattern 4
python tools/render_octopus_boss.py --verify
```
