# 문어지지마 — Unity 게임 시스템 개발 프롬프트

## 1. 프로젝트 개요

현재 Unity C#으로 개발 중인 **문어지지마** 게임의 전체 시스템을 아래 기획에 맞춰 구현 및 수정해 주세요.

- 게임명: 문어지지마
- 장르: 2D 탑뷰 뱀서라이크
- 플레이 방식: 2인 협동 멀티플레이
- 핵심 시스템: 몬스터 전투, 경험치 성장, 속성 획득, 요소 합성, 유물 수집, 스테이지 진행, 보스전

**중요 개발 원칙**

1. 기존 프로젝트의 코드와 구조를 먼저 분석해 주세요.
2. 이미 정상 작동하는 기능은 최대한 유지해 주세요.
3. 중복 기능이나 불필요한 코드는 정리하되 기존 기능에 영향을 주지 않도록 해 주세요.
4. 멀티플레이 환경에서 두 플레이어의 데이터가 정상적으로 동기화되도록 구현해 주세요.
5. 새로운 기능을 구현하기 전 기존 시스템과 충돌하는 부분이 있는지 확인해 주세요.
6. 아래에서 확정되지 않은 규칙은 임의로 결정하지 말고 먼저 보고해 주세요.

---

## 2. 게임 시작 및 기본 진행

### 게임 시작

- 게임은 2인 협동 플레이를 기준으로 구성합니다.
- 게임 시작 시 각 플레이어에게 기본 속성 1개를 지급합니다.
- 두 플레이어는 같은 필드에서 몬스터와 전투합니다.
- 몬스터는 스테이지에 따라 지속적으로 생성됩니다.
- 플레이어는 몬스터를 처치하여 경험치, 속성, 유물 조각 등의 보상을 획득합니다.

### 게임 진행 흐름

게임 시작 → 스테이지 시작 → 몬스터 처치 → 유물 조각 획득 → 중앙 오브젝트 납품 → 요구 수량 달성 → 스테이지 클리어 → 능력치 선택 → 3초 카운트다운 → 다음 스테이지 시작

5의 배수 스테이지에서는 보스전을 진행합니다.

## 3. 스테이지 시스템

### 유물 조각 수집

- 필드 중앙에 유물 조각을 납품하는 오브젝트를 설치합니다.
- 몬스터 처치 시 일정 확률로 유물 조각이 드랍됩니다.
- 플레이어는 유물 조각을 최대 1개까지 소지할 수 있습니다.
- 이미 조각을 소지한 플레이어는 추가 조각을 획득할 수 없습니다.
- 중앙 오브젝트에 접근하면 소지한 조각을 자동으로 납품합니다.
- 납품 시 소지한 조각이 제거되고 오브젝트의 누적 수량이 증가합니다.
- 납품 수량은 두 플레이어가 공유합니다.
- 스테이지마다 요구하는 조각 수량을 설정할 수 있도록 구현합니다.

### 스테이지 클리어

필요한 유물 조각을 모두 납품하면 다음 처리를 실행합니다.

1. 중앙 오브젝트 활성화
2. 스테이지 클리어 처리
3. 필드의 모든 몬스터 제거
4. 몬스터 생성 중단
5. 플레이어 공격 및 전투 처리 중단
6. 능력치 선택 UI 표시

몬스터 제거로 인해 추가 경험치나 아이템이 비정상적으로 생성되지 않도록 처리해 주세요.

### 다음 스테이지 전환

- 각 플레이어에게 능력치 선택 UI를 표시합니다.
- 모든 플레이어가 선택을 완료할 때까지 대기합니다.
- 두 플레이어 모두 선택을 완료하면 3초 카운트다운을 시작합니다.
- 카운트다운이 끝나면 다음 스테이지가 시작됩니다.
- 다음 스테이지 시작 시 몬스터 생성과 전투를 재개합니다.
- 플레이어가 획득한 능력치, 속성, 요소는 유지합니다.
- 이전 스테이지의 유물 납품 진행도는 초기화합니다.

## 4. 경험치 및 레벨업 시스템

### 경험치 획득

- 몬스터 처치 시 경험치 구슬을 생성합니다.
- 플레이어가 경험치 구슬에 접근하면 자동으로 획득합니다.
- 경험치가 일정 수치에 도달하면 레벨업합니다.
- 레벨업에 필요한 경험치는 레벨에 따라 증가하도록 구성합니다.

기존 경험치 시스템이 구현되어 있다면 해당 구조를 유지해 주세요.

### 능력치 강화

스테이지 클리어 시 아래 능력치 중 무작위 3개를 표시하고 플레이어가 1개를 선택하도록 구현합니다.

**기본 능력치**
- 이동속도 증가
- 최대 체력 증가
- 속성 데미지 증가
- 속성 쿨타임 감소
- 요소/특수요소 데미지 증가
- 요소/특수요소 쿨타임 감소

능력치 선택 UI는 각 플레이어가 개별적으로 사용합니다.

선택한 능력치는 해당 플레이어에게만 적용하며, 다음 스테이지에도 유지합니다.

능력치 증가 수치는 기존 프로젝트에 설정된 값을 우선 사용합니다.

## 5. 속성 시스템

### 기본 속성

게임에는 총 4개의 기본 속성이 존재합니다.

**풀**
- 몬스터 주변에 가시를 생성하여 공격합니다.

**불**
- 캐릭터를 중심으로 일정 시간 화염지대를 생성합니다.

**물**
- 플레이어 전방으로 물 포탄을 발사합니다.

**전기**
- 플레이어 전방으로 전류를 방출합니다.

### 속성 획득

- 게임 시작 시 기본 속성 1개를 지급합니다.
- 몬스터 처치 시 일정 확률로 속성 아이템이 생성됩니다.
- 플레이어가 속성 아이템을 획득하면 보유 속성에 추가합니다.
- 속성은 최대 3개까지 보유할 수 있습니다.
- 속성마다 개별 공격 기능과 쿨타임을 가집니다.
- 기존 자동 공격 시스템과 연동합니다.

### 속성 성장

- 속성 공격은 기존 자동 공격 순환 시스템을 사용합니다.
- 속성 데미지와 쿨타임은 능력치 강화의 영향을 받습니다.
- 각 속성의 공격 효과는 독립적으로 관리합니다.

## 6. 요소 합성 시스템

### 합성 기본 규칙

- 서로 다른 속성 2개를 조합하여 요소를 생성합니다.
- 합성에 사용된 속성 2개는 보유 목록에서 제거합니다.
- 합성된 요소는 요소 보유 목록에 추가합니다.
- 요소는 최대 3개까지 보유할 수 있습니다.
- 합성 후에도 새로운 속성을 획득할 수 있습니다.
- 동일한 속성 조합은 동일한 요소를 생성합니다.
- 합성된 요소는 기존 자동 공격 시스템에 등록합니다.

### 요소 목록

다음 6가지 요소를 구현 대상으로 사용합니다.

**탄산수**
- 탄산수 파도가 필드를 돌아다니며 몬스터에게 피해를 입힙니다.

**고추**
- 플레이어 주변 사방으로 고추를 발사하여 몬스터에게 피해를 입힙니다.

**나무**
- 거대한 나무를 생성합니다.
- 나무에서 열매가 떨어지며 주변 몬스터에게 지속적으로 피해를 입힙니다.

**레몬**
- 플레이어 주변 사방으로 레몬을 발사하여 몬스터에게 피해를 입힙니다.

**안개**
- 일정 범위에 안개를 생성합니다.
- 안개 범위에 들어온 몬스터는 이동속도가 감소합니다.
- 범위 안에 있는 동안 지속 피해를 입습니다.

**청염**
- 일정 시간 동안 연쇄 전류를 방출합니다.
- 전류에 맞은 몬스터에게 피해를 입힙니다.

각 요소의 데미지, 범위, 지속시간, 쿨타임은 개별적으로 설정할 수 있도록 구현합니다.

### 합성 시 주의 사항

현재 기획에서 요소별 정확한 속성 조합과 합성 가능 시점은 최종 확정되지 않았습니다.

따라서 기존 프로젝트에 정의된 합성 조합이 있다면 우선 유지해 주세요.

합성 규칙을 코드에 고정하지 말고, 추후 조합을 변경하기 쉬운 데이터 기반 구조로 작성해 주세요.

요소 3개를 모두 소지한 상태에서 추가 합성을 시도할 경우 임의로 요소를 삭제하지 말고 합성을 제한해 주세요.

## 7. 보스 시스템

### 보스 등장

- 5스테이지마다 보스가 등장합니다.
- 보스 등장 스테이지는 5, 10, 15스테이지입니다.
- 보스는 일반 몬스터보다 높은 체력과 공격력을 가집니다.
- 보스마다 고유한 공격 패턴을 사용할 수 있도록 구성합니다.

### 보스 처치

- 보스를 처치하면 보스 스테이지가 클리어됩니다.
- 보스 처치 시 특수요소 보상을 지급합니다.
- 이후 능력치 선택 및 다음 스테이지 진행 시스템과 연동합니다.

### 특수요소

- 특수요소는 일반 요소와 구분하여 관리합니다.
- 특수요소는 별도의 공격 효과를 가집니다.
- 특수요소도 데미지 및 쿨타임 능력치의 영향을 받습니다.

기존 특수요소 시스템이 구현되어 있다면 해당 구조를 유지해 주세요.

## 8. 2인 멀티플레이 동기화

다음 데이터가 정상적으로 동기화되도록 구현해 주세요.

**공유 데이터**
- 현재 스테이지
- 몬스터 생성 및 처치 상태
- 유물 조각 납품 수량
- 중앙 오브젝트 활성화
- 스테이지 클리어 상태
- 보스 등장 및 처치
- 다음 스테이지 카운트다운

**개별 플레이어 데이터**
- 체력 및 최대 체력
- 이동속도
- 경험치 및 레벨
- 보유 속성
- 보유 요소
- 특수요소
- 능력치 강화
- 유물 조각 소지 여부
- 능력치 선택 완료 여부

Unity Relay 및 기존 네트워크 구조를 유지하면서 구현해 주세요.

호스트와 클라이언트에서 중복으로 몬스터가 생성되거나 아이템이 중복 획득되지 않도록 처리해 주세요.

스테이지 클리어 판정과 다음 스테이지 시작은 호스트 또는 서버 권한으로 관리해 주세요.
